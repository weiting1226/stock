fumée 搶位設定

每月1號 00:00（台北時間）開放次月訂位。在這裡先填好想搶的日期/時段/人數優先順序， 排程會在開放的瞬間依序自動嘗試。

1 · 連線設定

直接用你的瀏覽器呼叫 GitHub API 把設定寫回這個 repo， 不會經過任何第三方伺服器。建議到 GitHub → Settings → Developer settings → Fine-grained tokens 建立一組「只限這個repo、只給 Contents 讀寫」的token，效期設短一點（例如7天）。 Token 只會存在這台瀏覽器的 localStorage，隨時可以按「忘記token」清掉。

3 · 搶位優先順序（由上而下依序嘗試，第一個成功就停止）

fumée吧檯座（1–4人）只開 17:30 與 20:30；5人以上包廂只開 19:00。 日期請填「下個月」的日期——每次搶位前記得回來更新這份清單。

4 · 儲存

這裡存的不含姓名/電話/Email——那些是個資，改用 GitHub Secrets 單獨設定一次即可（BOOKING_NAME / BOOKING_PHONE / BOOKING_EMAIL / NOTIFY_EMAIL_TO），還有登入用的 INLINE_STORAGE_STATE_B64 與寄信用的 SMTP_*。 完整步驟見 repo 內 fumee_booking/README.md，或直接開 Settings → Secrets and variables → Actions。

重要提醒

  • 這類自動化工具通常會落在訂位平台使用條款的灰色地帶（多數平台明文禁止自動化/機器人訂位）；本工具刻意只用單一帳號、正常速度嘗試，不做繞過驗證碼、偽造多帳號、灌爆伺服器等行為，但仍建議自行評估風險，帳號有被平台限制的可能。
  • GitHub Actions 的排程時間不保證絕對準時，且執行環境的IP是GitHub共用IP，有被平台判定為異常流量的風險；這不是能完全消除的限制。
  • inline 頁面的實際畫面結構未經驗證（開發時網路連不到 inline.app），正式使用前務必先用 workflow 的 inspect 模式跑一次，核對 fumee_booking/locators.py 的選擇器是否正確。
